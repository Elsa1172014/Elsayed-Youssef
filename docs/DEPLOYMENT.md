# دليل التشغيل (مبسّط)

> **القرار المعتمد:** المنتج تطبيق **ويب** يعمل على أي جهاز له متصفح (متصفح التلفزيون، الهاتف، الحاسوب). **نشر المتاجر ملغى**: لا حاجة لحسابات Apple أو Google أو Samsung أو LG ولا لشهادات توقيع.
>
> لم يُنشأ أي حساب ولم يُنشر أي شيء خارجياً. كل ما هو مطلوب جاهز ليعمل **بأمر واحد** على أي جهاز يشغّل Docker.

## ما الذي ستحصل عليه بعد التشغيل

- موقع يعمل بالعربية والإنجليزية: تسجيل بالاسم وكلمة المرور، قنواتي، دليل البرامج، بحث، توصيات.
- **كتالوج القنوات المجانية المفتوحة** من دليل iptv-org (نحو 9,500 قناة من 178 دولة بكل اللغات والفئات)، يُحمَّل ويُحدَّث تلقائياً كل 24 ساعة، مع فلترة بالدولة والفئة واللغة وزر «أضف الكل إلى قنواتي».
- قاعدة Postgres وخادم وخدمة خلفية لفحص صحة الروابط، و HTTPS تلقائي إذا كان لديك اسم نطاق.

**الحد القانوني ثابت:** قنوات مجانية ومفتوحة فقط، أو مصادر يملكها المستخدم ويدخلها بنفسه. لا فك تشفير ولا card-sharing ولا تجاوز DRM. الكتالوج يستبعد تلقائياً قنوات **blocklist** لدى iptv-org (طلبات الإزالة وغير اللائق) والقنوات المغلقة وفئة البالغين والروابط التي تحتاج ترويسات خاصة.

## الخطوات (اختر طريقة واحدة)

### الطريقة 1: على حاسوبك أو جهاز في بيتك (مجانية تماماً)

يصلح أي حاسوب يبقى شغّالاً (أو Raspberry Pi 4 فأعلى، أو حاسوب قديم).

1. ثبّت Docker: على ويندوز/ماك من **Docker Desktop** (docker.com، زر Download)، وعلى لينكس نفّذ `curl -fsSL https://get.docker.com | sh`.
2. نزّل المشروع (زر **Code ← Download ZIP** في GitHub، أو `git clone`) وافتح الطرفية داخل المجلد.
3. نفّذ:
   ```bash
   ./scripts/setup.sh
   ```
   (على ويندوز استخدم **Git Bash** أو WSL.) يُنشئ الأمر ملف `.env` بكلمات سر عشوائية ثم يبني كل شيء ويشغّله.
4. افتح `http://localhost` على نفس الجهاز، أو `http://<عنوان-الجهاز-في-الشبكة>` من التلفزيون والهاتف.
5. أنشئ حسابك، ثم **قنوات مجانية ← اختر لغة أو دولة ← أضف الكل إلى قنواتي**.

**للوصول من خارج البيت مجاناً:** ثبّت `cloudflared` ونفّذ `cloudflared tunnel --url http://localhost:80` فيعطيك رابطاً مؤقتاً يعمل من أي مكان (يتغيّر في كل تشغيل). للرابط الثابت تحتاج اسم نطاق.

### الطريقة 2: خادم سحابي دائم (مجاني أو شبه مجاني)

> الأسعار والباقات المجانية تتغيّر؛ تحقق منها في موقع كل مزوّد قبل البدء.

**أ) Oracle Cloud «Always Free» (مجاني، يحتاج بطاقة للتحقق فقط):**

1. أنشئ حساباً في cloud.oracle.com (زر **Start for free**).
2. **Compute ← Instances ← Create instance**: اختر الصورة **Ubuntu 24.04** والشكل **Ampere (ARM) VM.Standard.A1.Flex** بـ 2 OCPU و 12 GB. (إن ظهر «Out of capacity» جرّب لاحقاً أو منطقة أخرى.) نزّل مفتاح SSH الذي يعرضه لك.
3. افتح المنفذين 80 و 443: في صفحة الشبكة (**VCN ← Security List ← Add Ingress Rules**) أضف قاعدتين لـ TCP على المنفذ 80 ثم 443 من `0.0.0.0/0`.
4. اتصل بالخادم (`ssh -i المفتاح ubuntu@عنوان-IP`) ونفّذ:
   ```bash
   sudo iptables -I INPUT -p tcp --dport 80 -j ACCEPT && sudo iptables -I INPUT -p tcp --dport 443 -j ACCEPT
   sudo apt-get update && sudo apt-get install -y netfilter-persistent && sudo netfilter-persistent save
   curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER && newgrp docker
   git clone https://github.com/Elsa1172014/Elsayed-Youssef.git && cd Elsayed-Youssef
   git checkout claude/architecture-roadmap-i2z5iz   # احذف هذا السطر بعد دمج الـ PR في main
   ```
5. **اسم نطاق مجاني:** في duckdns.org سجّل الدخول وأنشئ نطاقاً فرعياً (مثل `mytv.duckdns.org`) واجعله يشير إلى عنوان IP العام للخادم.
6. شغّل مع النطاق (يحصل على شهادة HTTPS تلقائياً):
   ```bash
   ./scripts/setup.sh mytv.duckdns.org
   ```
7. افتح `https://mytv.duckdns.org`.

**ب) أي VPS مدفوع رخيص** (Hetzner أو DigitalOcean أو غيرهما، عادةً بضعة دولارات شهرياً، يكفي 2 GB ذاكرة): أنشئ خادم Ubuntu، ثم نفّذ الخطوات 4 إلى 7 نفسها (بدون سطر iptables إلا إذا كان الجدار الناري يمنع المنفذين).

### قاعدة Postgres مُدارة (اختيارية)

القاعدة المرفقة تعمل افتراضياً وبياناتها على قرص الخادم. إن أردت قاعدة خارجية (مثل الباقات المجانية في Neon أو Supabase؛ قد تتوقف أو تُحذف عند الخمول، فتحقق من شروطها):

1. أنشئ قاعدة ونسخ رابط الاتصال (`postgres://...?sslmode=require`).
2. أضف في `.env` سطر: `DATABASE_URL=الرابط`.
3. شغّل: `docker compose up -d --build --no-deps api worker web`.

## الصيانة

| المهمة | الأمر |
|---|---|
| التحديث | `git pull && docker compose up -d --build` |
| السجلات | `docker compose logs -f worker` (مزامنة الكتالوج) أو `api` |
| النسخ الاحتياطي | `docker compose exec -T db pg_dump -U receiver receiver > backup.sql` **واحتفظ بنسخة من `.env`** (فيه مفتاح التشفير؛ بدونه تضيع بيانات الدخول المحفوظة لحسابات Xtream) |
| الإيقاف | `docker compose down` (أضف `-v` لحذف البيانات نهائياً) |
| حجب قناة (طلب إزالة) | `docker compose exec worker npx tsx src/jobs/cli.ts block <معرّف-القناة>` |
| إعادة مزامنة الكتالوج فوراً | `docker compose exec worker npx tsx src/jobs/cli.ts sync-iptv-org` |

## حدود يجب أن تعرفها

1. **بعض القنوات المجانية لن تعمل في كل متصفح** (ليس عيباً في المشروع):
   - الموقع على HTTPS لا يستطيع تشغيل روابط `http://` (حظر المحتوى المختلط). الاستيراد يفضّل روابط HTTPS تلقائياً.
   - متصفحات Chrome وFirefox وEdge تحتاج أن يسمح مصدر البث بـ CORS وكثير من المصادر لا تسمح. Safari وiOS ومعظم متصفحات التلفزيون تستخدم التشغيل المدمج ولا تحتاج CORS. جرّب متصفحاً آخر إن فشلت قناة.
   - الحل الكامل يتطلب تمرير البث عبر خادمك، وهذا غير مبني عمداً (تكلفة نطاق ترددي، والقاعدة أن الخادم لا يمرّر البث). يمكن إضافته لاحقاً كخيار للقنوات الرسمية المجانية فقط.
2. **لا يوجد استرجاع لكلمة المرور** (لا بريد في الحسابات). من ينساها يفقد حسابه. يمكن إضافة بريد أو رموز استرجاع لاحقاً.
3. حدود محاولات الدخول محفوظة في ذاكرة الخادم؛ يكفي هذا لنسخة واحدة. عند تشغيل أكثر من نسخة تُنقل إلى Redis.
4. تحميل الكتالوج يتطلب وصول الخادم إلى `iptv-org.github.io`. إن حُجب في شبكتك فاضبط `IPTV_ORG_API` على نسخة مرآة.
5. قائمة القنوات الرسمية/FAST اليدوية (`catalog/official.json`) فارغة عمداً؛ لا تضف إليها إلا روابط تحققتَ أنها منشورة من القناة نفسها.

## استكشاف الأخطاء

- **`./scripts/setup.sh` يقول إن Docker غير مثبّت:** أكمل الخطوة 1 وأعد فتح الطرفية.
- **الصفحة لا تفتح:** `docker compose ps` يجب أن يُظهر 4 خدمات تعمل (db وapi وworker وweb). راجع `docker compose logs api`.
- **HTTPS لا يعمل مع النطاق:** تأكد أن النطاق يشير إلى IP الخادم وأن المنفذين 80 و443 مفتوحان (في جدار المزوّد ومحلياً).
- **الكتالوج فارغ:** انتظر دقيقة أو دقيقتين بعد أول تشغيل ثم راجع `docker compose logs worker`.

## ملاحظات للمطورين (إنتاج)

- المصادقة: كلمات المرور بـ scrypt، جلسات عشوائية مخزّنة بصمتها فقط (30 يوماً)، حدّ محاولات لكل اسم ولكل IP، تغيير كلمة المرور يلغي الجلسات الأخرى، حذف الحساب يحذف كل بياناته.
- أسرار: `SECRET_KEY` (32 بايت base64) يُنشأ عشوائياً في `.env`؛ الصيغة مرقّمة `v1` لإمكان تدوير المفاتيح لاحقاً.
- حماية الجلب من الخادم: كل خطوة (بما فيها إعادة التوجيه) تُفحص ويُرفض أي عنوان خاص؛ يبقى خطر DNS rebinding متبقياً فشغّل الخادم في شبكة تمنع النطاقات الداخلية إن أمكن.
- الويب يحفظ الرمز في `localStorage`؛ سياسة CSP صارمة للسكربتات (same-origin فقط) في `deploy/Caddyfile`.
- CI يشغّل المكدّس كاملاً (setup ← migrations ← تسجيل ← مزامنة الكتالوج الحقيقي) في كل PR.

## قسم قنوات الاشتراك (Premium) والذكاء الاصطناعي

- تبويب «قنوات الاشتراك» دليل بيانات فقط (أسماء، شعارات، تصنيفات) للقنوات التي لا يوجد لها بث مجاني. لا يحتوي روابط بث ولا يفك أي تشفير؛ المشاهدة فقط عبر اشتراك Xtream الذي تملكه (يُضاف من «قنواتي ومصادري») ثم تربط قناتك بالإدخال.
- عبارة «لا يوجد بث مجاني» لا تعني بالضرورة أن القناة مشفّرة.
- زر ✦ بجانب كل قناة: تلخيص الآن/التالي، ترجمة، قنوات مشابهة. لتفعيل النموذج ضع `GEMINI_API_KEY` (Google Gemini، الأولوية الأولى) أو `ANTHROPIC_API_KEY` (Claude) في `.env`، واختيارياً `AI_MODEL` لتغيير النموذج (الافتراضي `gemini-2.5-flash`)؛ يُرسل اسم القناة ونص الدليل فقط. بدونه يعمل ملخص بسيط محلي.

## النشر على Vercel

مسار إضافي بجانب Docker (لم يُحذف). يعمل مجاناً على الخطة المجانية (Hobby) مع قاعدة Postgres مجانية من Neon.

> **مهم:** الموقع الحالي `gfs-arabi-ahla-….vercel.app` يخدم التطبيق القديم الموجود في جذر المستودع (مصمم التقييمات). **لا تغيّر إعداداته.** أنشئ مشروعاً **جديداً** من نفس المستودع بالخطوات أدناه، فيعمل المستقلان دون تأثير أحدهما على الآخر.

### الخطوات (بالنقرات)
1. في Vercel: **Add New → Project** ثم اختر مستودع `Elsayed-Youssef` (Import).
2. في شاشة الإعداد اضغط **Root Directory → Edit** واختر `deploy/vercel`. تأكد أن خيار *Include source files outside of the Root Directory* مفعّل (الافتراضي). اترك Framework = Other وأوامر البناء كما هي (مأخوذة من `vercel.json`).
3. افتح **Environment Variables** وأضف قبل أول Deploy:
   - `SECRET_KEY`: ناتج الأمر `openssl rand -base64 32` (يشفّر بيانات اشتراك Xtream؛ إن فُقد لا تُفكّ البيانات القديمة).
   - `CRON_SECRET`: أي نص عشوائي طويل (`openssl rand -hex 24`)؛ تستخدمه Vercel تلقائياً لاستدعاء المزامنة اليومية.
   - لزر الذكاء الاصطناعي: `GEMINI_API_KEY` (مفتاح Google Gemini؛ إن وُجد يُستخدم أولاً) أو `ANTHROPIC_API_KEY`، واختيارياً `AI_MODEL`. بدون أي منهما يعمل ملخص بسيط محلي.
4. **قاعدة البيانات:** من تبويب **Storage** في المشروع اختر **Create Database → Neon (Postgres)** واربطها بالمشروع لكل البيئات. يضيف الربط `DATABASE_URL` تلقائياً. (إن ظهر عدة متغيرات فالمطلوب `DATABASE_URL` ذو الاتصال المُجمَّع Pooled.) الجداول تُنشأ تلقائياً عند أول طلب.
5. اضغط **Deploy**. بعد النجاح افتح الرابط، سجّل حساباً، وتأكد أن `/healthz` يعيد `ok`.
6. **أول مزامنة للقنوات:** من **Settings → Cron Jobs** اضغط **Run** بجانب `/api/cron`. تملأ المزامنة دليل القنوات المجانية ودليل قنوات الاشتراك (دقيقة تقريباً). بعدها تعمل تلقائياً يومياً الساعة 03:00 UTC.

### كيف تعاملنا مع قيود Vercel
| القيد | الحل |
|---|---|
| لا حاويات دائمة ولا Worker | الـ API دالة واحدة (`api/index.ts`) تشغّل Fastify نفسه؛ والـ Worker استُبدل بـ Cron يومي (`api/cron.ts`) يزامن ويفحص دفعة من البثوث. |
| مهلة تنفيذ الدالة | مهلة المزامنة 60 ثانية. إن تجاوزتها (يظهر خطأ 500 في Logs) شغّل المزامنة من جهازك مرة واحدة: `cd services/api && DATABASE_URL="…" npm run sync-iptv-org`. |
| لا تخزين محلي | كل شيء في Postgres؛ ملفات الـ SQL تُنسخ مع الدالة عند البناء. |
| اتصالات قاعدة البيانات | كل نسخة دالة تستخدم اتصالين كحد أقصى (`PG_POOL_MAX`)، ويُنصح بعنوان Neon المُجمَّع. |
| الخطة المجانية: Cron مرة يومياً فقط | يكفي للدليل. فحص الصحة يعالج 100 بث يومياً (`HEALTH_BATCH`) وليس كل 5 دقائق كما في Docker. |

### ما لا تغطيه هذه الخطوات
- نُفّذ هذا المسار واختُبر محلياً (تشغيل الدوال ضد قاعدة اختبار: التسجيل وحماية Cron)، لكنه **لم يُنشر فعلياً على Vercel**؛ إن ظهر خطأ في أول بناء أرسل نص السجل لتعديله.
- قيود البث ذاتها (CORS والمحتوى المختلط) تنطبق هنا أيضاً.
